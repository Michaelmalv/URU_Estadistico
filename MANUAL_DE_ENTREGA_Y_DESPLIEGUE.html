1 Objetivo y Principio de Soberanía Tecnológica

El objetivo de este manual es garantizar que el equipo técnico institucional (Municipio del DMQ / Secretaría de Territorio, Hábitat y Vivienda) mantenga autonomía técnica absoluta sobre el código, las bases de datos y la infraestructura web, asegurando que puedan clonar, programar, administrar y desplegar la plataforma sin depender de cuentas personales ajenas ni intermediarios.

📌 Los 4 Pilares de Infraestructura Institucional:
  1. Repositorio GitHub Propio: Para almacenar el código fuente, recibir aportes del equipo técnico y gobernar las versiones.
  2. Base de Datos PostgreSQL Propia en Supabase: Servidor cloud propio para alojar métricas de Seguridad, Economía (LUAEs) y Valor de Suelo.
  3. Cuenta y Access Token Propio en Mapbox (Obligatorio): Proveedor cartográfico para renderizar mapas 3D con restricción a dominios municipales.
  4. Servidor Cloud Propio en Vercel: Infraestructura web de alta disponibilidad con despliegue continuo ante cada git push.

2 Repositorios GitHub y Clonación Local Paso a Paso

El proyecto cuenta con dos repositorios oficiales listos para ser copiados:

  • Repositorio Maestro (Completo): https://github.com/Michaelmalv/URU_Estadistico.git (Contiene la aplicación en /web, datos cartográficos SIRES, matrices Excel analíticas y scripts).
  • Repositorio Despliegue Producción (Vercel Directo): https://github.com/Michaelmalv/Portal_Evaluacion_Proyectos_Estrategicos.git (Subárbol exclusivo para publicación directa).
Paso 2.1 Comandos para Clonar y Vincular a su Propio GitHub Institucional 
# 1. Clonar el repositorio maestro localmente
$ git clone https://github.com/Michaelmalv/URU_Estadistico.git
$ cd URU_Estadistico

# 2. Re-vincular el repositorio a su nueva cuenta institucional de GitHub
$ git remote set-url origin https://github.com/SuOrganizacion/URU_Estadistico.git

# 3. Subir las ramas principales al nuevo servidor institucional
$ git push -u origin main
$ git push origin master
Paso 2.2 Instalación y Ejecución en Entorno Local (Desarrollo) 
# Navegar al directorio de la aplicación web
$ cd web

# Instalar las dependencias de Node.js (requiere Node v18, v20, v22 o superior)
$ npm install

# Iniciar el servidor local de desarrollo con Fast Refresh
$ npm run dev

Abra en su navegador http://localhost:3000. Cualquier cambio que realice en los archivos .js o .css se refresca inmediatamente en pantalla.

3 Base de Datos Propia en Supabase e Inyección SQL Completa

Para que las estadísticas de Seguridad, Economía (LUAEs) y Valor de Suelo funcionen con su propio backend, se incluye el script maestro de migración e inyección SQL automática con 1 clic.

Paso 3.1 Crear Proyecto Propio en Supabase (Gratuito / Cloud)
  1. Ingrese a https://supabase.com con el correo institucional.
  2. Haga clic en "New Project".
  3. Asigne nombre (ejemplo: portal-estrategicos-dmq), defina contraseña segura y elija región cercana (South America / São Paulo o US East).
Paso 3.2 Ejecución del Script de Inyección SQL Maestro

En la raíz del repositorio clonado se encuentra el archivo maestro listo para ejecutar: scripts/supabase_migration_complete.sql (59 KB con esquema relacional, restricciones, índices y seed data consolidado 2019-2026).

  1. En el panel lateral de Supabase, haga clic en SQL Editor.
  2. Haga clic en "New Query".
  3. Abra scripts/supabase_migration_complete.sql, copie todo el contenido y péguelo en el editor.
  4. Presione el botón verde "RUN".

Resumen de estructura DDL inyectada por el script para el funcionamiento del portal:

-- Extensión de identificadores y tablas relacionales maestras
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE TABLE proyectos (id UUID PRIMARY KEY DEFAULT uuid_generate_v4(), nombre TEXT UNIQUE NOT NULL, categoria TEXT, ubicacion TEXT, extension TEXT);
CREATE TABLE seguridad_estadisticas (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, proyecto_id UUID REFERENCES proyectos(id) ON DELETE CASCADE, anio TEXT NOT NULL, variable TEXT NOT NULL, valor NUMERIC, tipo TEXT DEFAULT 'observado');
CREATE TABLE economia_registros (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, sector_raw TEXT, movimiento_raw TEXT, fecha_impresion DATE);
CREATE TABLE valor_suelo (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, proyecto TEXT NOT NULL, descripcion TEXT, valor_2022_2023 NUMERIC, valor_2024 NUMERIC, valor_2026 NUMERIC);
CREATE TABLE senderos_fichas (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, proyecto_id UUID REFERENCES proyectos(id) ON DELETE CASCADE, anio INT, ejecutor TEXT, presupuesto TEXT, extension TEXT, beneficiarios TEXT, fecha TEXT);
⚠️ REGLA OBLIGATORIA: POLÍTICAS DE LECTURA PÚBLICA (ROW LEVEL SECURITY - RLS):
Supabase bloquea por defecto las consultas web públicas. El script ejecuta automáticamente las siguientes políticas indispensables para que el frontend pueda leer los datos sin token administrativo: 
-- Activación de RLS y permisos públicos de solo lectura para la aplicación web
ALTER TABLE proyectos ENABLE ROW LEVEL SECURITY; ALTER TABLE seguridad_estadisticas ENABLE ROW LEVEL SECURITY;
ALTER TABLE economia_registros ENABLE ROW LEVEL SECURITY; ALTER TABLE valor_suelo ENABLE ROW LEVEL SECURITY; ALTER TABLE senderos_fichas ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Lectura publica proyectos" ON proyectos FOR SELECT USING (true);
CREATE POLICY "Lectura publica seguridad" ON seguridad_estadisticas FOR SELECT USING (true);
CREATE POLICY "Lectura publica economia" ON economia_registros FOR SELECT USING (true);
CREATE POLICY "Lectura publica valor suelo" ON valor_suelo FOR SELECT USING (true);
CREATE POLICY "Lectura publica senderos" ON senderos_fichas FOR SELECT USING (true);
Paso 3.4 Copiar Credenciales Institucionales de Supabase

En Supabase vaya a Project Settings ➔ Data API y copie sus dos variables para la aplicación:

Parámetro en Supabase Variable de Entorno Descripción
Project URL NEXT_PUBLIC_SUPABASE_URL URL HTTPS del servidor (ej. https://xxxx.supabase.co)
anon / public key NEXT_PUBLIC_SUPABASE_ANON_KEY Clave pública segura para consultas frontend desde el navegador

4 Cuenta y Access Token Propio de Mapbox (OBLIGATORIO)

⚠️ SOBERANÍA CARTOGRÁFICA Y SEGURIDAD OBLIGATORIA:
Por normativas de ciberseguridad municipal, la institución DEBE generar su propio token de Mapbox. Jamás utilice tokens personales ajenos para evitar cortes imprevistos o bloqueos por límite de cuota.

Mapbox otorga 50.000 cargas de mapa mensuales completamente gratis, suficientes para la demanda ciudadana e interna del portal.

Paso 4.1 Registro de Cuenta Mapbox

Ingrese a https://account.mapbox.com y registre una cuenta oficial con el correo de la institución.

Paso 4.2 Creación de Token con Restricción de Dominio
  1. En la sección "Access Tokens", haga clic en "Create a token".
  2. Asigne nombre: Portal-DMQ-Produccion.
  3. En el campo "URL Restrictions", escriba los dominios permitidos (ejemplo: *.vercel.app y *.quito.gob.ec). Esto impide que terceros consuman su cuota de mapas.
  4. Copie el token generado (inicia con pk.eyJ1...). Corresponde a: NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN.

5 Despliegue en Producción Cloud con Vercel

Vercel es la nube oficial de Next.js. Provee servidores de alta velocidad, certificados SSL HTTPS automáticos y publicación continua ante cada actualización en GitHub.

Paso 5.1 Conectar el Repositorio de GitHub en Vercel
  1. Inicie sesión en https://vercel.com con la cuenta institucional.
  2. Clic en "Add New..." ➔ "Project".
  3. Seleccione el repositorio URU_Estadistico (o Portal_Evaluacion_Proyectos_Estrategicos).
🚨 PASO CRÍTICO OBLIGATORIO: CONFIGURAR "ROOT DIRECTORY" EN "web"
Si conecta el repositorio maestro URU_Estadistico, en la pantalla de configuración de Vercel debe hacer clic en EDIT en "Root Directory" y escribir:
web
(Si no selecciona la subcarpeta "web", Vercel intentará compilar la raíz del repositorio y fallará al no encontrar package.json).
Paso 5.2 Inyectar las 3 Variables de Entorno en Vercel
Variable en Vercel Valor a Colocar Propósito
NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN pk.eyJ1... (Token propio Mapbox) Renderizado de mapas 3D y trazados viales
NEXT_PUBLIC_SUPABASE_URL https://xxxx.supabase.co Conexión a la base de datos PostgreSQL
NEXT_PUBLIC_SUPABASE_ANON_KEY eyJhbGci... (Anon Key Supabase) Lectura pública segura de estadísticas
Paso 5.3 Clic en "Deploy" y Archivo Local de Respaldo (.env.local)

Haga clic en "Deploy". En 60 segundos la web estará activa. Para trabajar en desarrollo local, cree el archivo web/.env.local:

NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN=pk.eyJ1xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.xxxxxxx

7 Sensibilidad del Proyecto, Resiliencia y Tolerancia a Fallos

🛡️ ARQUITECTURA RESILIENTE DE ALTA DISPONIBILIDAD (MOTOR HÍBRIDO):
Para asegurar que el portal municipal nunca sufra caídas ni muestre pantallas en blanco si la base de datos entra en pausa por inactividad de Supabase, el portal cuenta con un mecanismo de respaldo automático: si la conexión remota tarda o falla, el frontend consume de inmediato las fuentes locales precargadas en web/src/lib/, garantizando 100% de disponibilidad ciudadana 24/7.
